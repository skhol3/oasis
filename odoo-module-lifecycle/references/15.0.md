# Odoo 15.0 module lifecycle

What the [module lifecycle skill](../SKILL.md) needs on a 15.0 checkout. The values are the 15.0 row of the series table of the oasis tools (`tools/odoo_versions.py`), read from the 15.0 source (commit 3a28e5b0). The [19.0 reference](19.0.md) lists the same points for 19.0.

- Version proof: `odoo/release.py` declares `version_info = (15, 0, ...)` (doctor `odoo_release=15.0`); module manifests carry `15.0.x.y.z` versions, and a module of another series fails doctor's `module_series`.
- Demo data: Odoo 15.0 loads it unless told otherwise. `install-module` and test runs pass `--without-demo=all`: the option takes a value (`odoo/tools/config.py:111`), so bare it would swallow the next option, and any value turns demo data off for every module installed. There is no `--with-demo`: `install-module --with-demo` and `init-dev-database --with-demo` pass nothing and get the default demo data.
- Users: `init-dev-database` writes the groups of `[development]` users to `res.users.groups_id`.
- Second server port: `--longpolling-port` (`longpolling_port` in `odoo.conf`, `odoo/tools/config.py:136`), given a free one on test runs and linked worktrees.
- Tests: `--test-tags /<module>[:Class.method]` does not imply `--stop-after-init` (`odoo/tools/config.py:534`); oasis passes it on every test run.
- Developer mode: `--dev=` also takes the debuggers `pdb`, `ipdb`, `pudb`, `wdb` and `werkzeug` (`all` is `pdb,reload,qweb,werkzeug,xml`).
