# Subagents

Gentle Shell subagents (for example `gentle-ai-worker` and `gentle-ai-verify`) receive only the tools in their allowlist, so they do not see the `oasis_*` tools by default. oasis ships an overlay template, [`pi/agent-overlays/oasis.json`](../pi/agent-overlays/oasis.json), that adds the tools to both agents; `oasis_update_module` goes to the worker only, because the verify agent stays read-only. Run `/oasis setup` once in Gentle Shell: it installs the overlay without asking (it also shows the checkout's status and setup plan, see [The /oasis command](gentle-shell-layer.md#the-oasis-command)) and says what it did; oasis reminds you at session start when the overlay is missing or outdated.

The overlay is for Gentle Shell only. In a session that Gentle Shell did not start, `/oasis setup` writes no overlay and its report ends with `subagent overlay: it applies only to Gentle Shell, and this session is not running in it; nothing written.`, and no reminder appears. A session counts as Gentle Shell when `PI_PROGRAM_STATUS_APP` is `gentle-shell` (Gentle Shell's launcher sets it) or `GENTLE_PI_CONFIG_HOME` is an absolute path (the config home named explicitly); a `~/.gentle-shell` directory alone does not count.

- `/oasis setup` writes only `agent-overlays.d/oasis.json` under the Gentle AI config home (`$GENTLE_PI_CONFIG_HOME` when it is an absolute path, else `~/.gentle-shell/gentle-ai`). It works outside an Odoo project, says `subagent overlay: already installed, nothing to do (<file>).` when the overlay is up to date, and only the user can run it: no agent tool triggers it. Start a new session or `/reload` afterwards.
- That folder is user configuration: Gentle Shell updates do not replace it. Run `/oasis setup` again after an oasis update that changes the template.
- If Gentle AI renames an agent, the overlay entry for the old name only produces a notice until an oasis update renames it.
- `oasis_test_module` runs each test on a new disposable database of the checkout's `<test_prefix>` namespace and drops it at the end (an explicit `database` or a configured `test_database` is reset and reused instead), so a verify subagent with the overlay can do so too. Its summary line then ends with `database_lifecycle=disposable dropped=<yes|no>`. There is no agent tool for `oasis gc`: removing leftovers is up to the user.
- Without the overlay, subagents can still run the core through bash: `python3 /absolute/path/to/oasis/oasis --project <project root> <command>` (for example `test-module --compact <module>`).
