# Odoo 15.0 environment

What the [environment skill](../SKILL.md) needs on a 15.0 checkout. The values are the 15.0 row of the series table of the oasis tools (`tools/odoo_versions.py`), read from the 15.0 source (commit 3a28e5b0). The [19.0 reference](19.0.md) lists the same points for 19.0.

- Release: `odoo/release.py` declares `version_info = (15, 0, ...)`; `oasis doctor` reports it as `odoo_release=15.0` and, in a workspace with several series, `series=15.0`. Module manifests carry `15.0.x.y.z` versions (doctor `module_series`).
- Python: 3.7 to 3.12 (`MIN_PY_VERSION`, `MAX_PY_VERSION` in `odoo/__init__.py:19-20`; `odoo/cli/server.py:69` refuses a newer one); a workspace without named environments uses 3.9, the Python of the official 15.0 package (`FROM debian:bullseye`).
- PostgreSQL: 12 is the documented minimum (the source enforces none); `oasis setup` writes a compose file with `postgres:14`.
- Second server port: `--longpolling-port`, `longpolling_port` in `odoo.conf` (`odoo/tools/config.py:136`); `--gevent-port` does not exist.
- Developer mode: `--dev=` takes the debuggers `ipdb`, `pdb`, `pudb`, `wdb` and `qweb`, `reload`, `werkzeug`, `xml` (`odoo/tools/debugger.py:8`, `odoo/tools/config.py:287`); `all` is `pdb,reload,qweb,werkzeug,xml`. `reload` needs `inotify` or `watchdog`.
- Runtime requirements: Odoo 15.0 imports `pkg_resources` without listing setuptools, so an environment uv creates lacks it and `odoo-bin` stops with "No module named 'pkg_resources'"; `oasis setup` adds `setuptools<81` to `runtime.in`.
- python-ldap: the source pins `python-ldap==3.4.0`, which links `libldap_r` and does not build against OpenLDAP 2.6; on such a machine `oasis setup` proposes `python-ldap==3.4.4` in `overrides.txt`.
