# Odoo 15.0 backend

What the [backend skill](../SKILL.md) needs on a 15.0 checkout. Read from the 15.0 source (commit 3a28e5b0); paths are relative to its root. The [19.0 reference](19.0.md) lists the same points for 19.0.

- Source layout: the ORM is `odoo/models.py`, `odoo/fields.py` and `odoo/api.py`; `odoo/release.py` holds `version_info`, `odoo/__init__.py` the Python range.
- Python: 3.7 to 3.12 (`MIN_PY_VERSION`, `MAX_PY_VERSION` in `odoo/__init__.py:19-20`); the default environment is 3.9, so code for it cannot use `match` or `X | Y` type unions evaluated at run time (both need 3.10).
- Display name: override `name_get` (`odoo/models.py:1845`) and, for searching, `_name_search(name, args, operator, limit, name_get_uid)` (`:1917`). `_search_display_name` and `_rec_names_search` do not exist.
- SQL constraints: the `_sql_constraints` list of `(name, definition, message)` tuples (`odoo/models.py:497`); there are no `models.Constraint` or `models.Index` attributes.
- Grouping: the public `read_group(domain, fields, groupby, offset, limit, orderby, lazy)` (`odoo/models.py:2412`) returns dictionaries; the 19.0 `_read_group(domain, groupby, aggregates)` signature does not exist.
- Field aggregation: `group_operator=` (`odoo/fields.py:285`); `aggregator=` does not exist.
- Cache: `flush(fnames, records)` and `invalidate_cache(fnames, ids)` (`odoo/models.py:5668`, `5982`); there is no `flush_model`, `invalidate_recordset` or `odoo.tools.SQL`: pass parameters to `cr.execute(query, params)`.
- Access checks: `check_access_rights(operation, raise_exception)` for ACLs and `check_access_rule(operation)` for record rules (`odoo/models.py:3559`, `3565`); `check_access` and `has_access` do not exist.
- Controllers: `@route(type='json')` (`odoo/http.py:451`); `jsonrpc` is not a route type.
- Translations: `from odoo import _`; the environment has no `_` method.
- Same in both series: `@api.model_create_multi` (`odoo/api.py:421`), `Command` (`odoo/fields.py:3002`), `with_company`, `_check_company`.
