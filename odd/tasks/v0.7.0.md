# v0.7.0 — query tools for views and XML ids

Static summaries of Odoo XML data, next to model-info: the agent learns a model's views, what
extends them and where an XML id lives without opening or searching XML files. Source parsing
only, so nothing depends on the Odoo series.

## Specs

- S1. User (2026-11-20), choosing the content of 0.7.0: "Sigue la 0.7.0 con las herramientas de
  consulta (vistas, XML IDs, herencia)."; "el panel para luego"; the cleanup of `odoo19` names:
  "para la siguiente".
- S2. `view-info <model> [--type <tag>] [--module <technical>]`: the base views of the model
  (type = root tag of the arch, XML id, file:line, priority, mode) and, below each, the views that
  extend it, recursively, with their number of changes. A view without a model field takes the
  model of the view it inherits. `unresolved:` lists extensions whose inherited view is not in the
  scanned roots; `skipped:` lists files that are not well-formed XML. No views: exit 1.
- S3. `xmlid-info <module>.<name>`: where the id is defined (record with its model, template or
  menuitem) with its fields, the views that extend it and the files that reference it (XML,
  Python, CSV; inside its module also by the name alone). Unknown id: exit 1.
- S4. Both scan the same roots and skip the same directories as model-info, parse XML with expat,
  import or execute nothing, and use no environment, service or database.
- S5. Agent tools `oasis_view_info` and `oasis_xmlid_info`, active in Odoo projects and in the
  overlay of both subagents (read-only).
- S6. Follow-ups of the v0.6.0 review: a failed database existence probe ends the command
  instead of looking like a missing database; `--reuse` has tests for the configured and the
  slug-qualified default names.
