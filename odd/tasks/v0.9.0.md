# v0.9.0 — action panel

A menu to run Odoo operations by hand without remembering commands: one action catalog in the
core, shown as `oasis menu` in a terminal and as a pop-up panel in Gentle Shell. Every action
shows the exact command it runs.

## Specs

- S1. User (2026-11-20): "me gustaria un panel con menu para levantar con o sin demo, actualizar,
  instalar, en si los comandos que odoo permita, ya sea para puertos, bases, o algo como un perfil.
  El caso es el siguiente, cuando quiero probarlo de forma manual tengo que preguntar, cual es el
  comando para esto y para lo otro". Decisions: "en ambos, con catalogo comun, pero quiero algo
  emergente como cuando usas alt+k en gentle-shell"; "La ejecuta y muestra el comando
  (recomendado)"; profiles "Después (recomendado)"; "para no complicarno primero vamos por un panel
  propio"; Gentle Shell is never modified.
- S2. First version actions (user, 2026-11-23): "Servidor: levantar, detener, ver logs", "Módulos:
  instalar (con o sin demo), actualizar, estado", "Tests: módulo, clase, reutilizando base", "Bases y
  mantenimiento: crear, borrar, limpiar, doctor". Maintenance also offers migrate and worktree, which
  stay user-run.
- S3. Catalog: one table in the core (tools/) with, per action: id, group, label, the oasis command
  and options it builds, the inputs it asks for (module from the checkout's addon modules, database
  from list-databases, test class, yes/no options such as demo or reuse), whether it is destructive
  and whether it is user-run only. `oasis menu --catalog` prints it as JSON for the Gentle Shell
  panel; no other place lists the actions.
- S4. Server in the background: `oasis start --detach [odoo options]` starts the checkout's server
  detached, writes its output to `<logs>/<slug or main>/server.log` (`dev/logs/odoo19/server.log`
  without `[tooling].logs`), prints the pid, port and log path, and returns. The existing
  one-server-per-checkout record and `stop` are reused. Without `--detach` start is unchanged.
- S5. `oasis menu` (terminal): numbered groups and actions from the catalog, then the inputs; shows
  the exact command before running it; destructive actions require typing the database or `yes`.
  It refuses to run without a terminal (stdin not a TTY), so an agent cannot drive it.
- S6. Gentle Shell panel: `alt+o` (configurable with an environment variable; documented) and
  `/oasis menu` open an overlay built with the public Pi extension API (registerShortcut,
  ctx.ui.custom overlay, ui.select/input/confirm); it reads the catalog from `oasis menu --catalog`,
  asks the inputs, confirms destructive actions, runs the command and shows the command and its
  output (compact for tests and updates, as the agent tools do). "Ver logs" shows the end of
  server.log. The panel is user-run: no agent tool opens it.
- S7. The list of databases may start the database service as `list-databases` does today; the
  panel says it is waiting.
- S8. Contract: `menu` is a new command and `start --detach` a new option; nothing existing changes.
  The bash guard blocks agents from running `oasis menu` (user-run, like migrate and worktree-init),
  `--help` aside.
