# oasis v0.18.0: skills that say how to build Odoo code

The `odoo-<topic>` skills follow the Gentle Shell shape but carry almost no knowledge: their per-series
references list what changed, not how to build a model, a view or an ACL. v0.18.0 adds task recipes.

## Specs

- S1. Recipes per task (user: "son una mierda y las tablas de referencia? no dicen como crear un model,
  una vista, nada de nada, se suponia que ibamos a seguir el modelo de skills de gentle-shell"; choice:
  "Planear v0.18.0 con recetas por tarea"). Each code skill's Decision Gates send the agent to a recipe
  under `references/` as Gentle Shell skills do (for example `gentle-ui-design`). Each recipe gives,
  in order: when to use it, the files to create or touch in their order (manifest `data` order
  included), one minimal working example written once in the form of the newest supported series, a
  "changed in" table (S8), the usual mistakes, and the oasis command that verifies it.
- S9. Official documentation (user: "sersiorate ademas con info de oddo oficial y actualizada"): each
  recipe has a line `Official docs:` with the official Odoo documentation page of its topic for every
  series it is checked against (`https://www.odoo.com/documentation/<series>/...`), and its content is
  cross-checked against those pages; where the official page and the source disagree, the source of
  the checked commit wins and the recipe says what the page says. Adding a series adds its page.
- S2. Backend (choice: "Backend: modelo nuevo, herencia, compute/constraint"): in `odoo-backend`, a
  minimal module (`__manifest__.py`, `__init__.py`), a new model with its fields, `_inherit` and
  `_inherits` extension, computed fields with `@api.depends`, constraints, and `create`/`write`
  overrides.
- S3. Views (choice: "Vistas: form/list/search, acción, menú, herencia XPath"): in
  `odoo-views-frontend`, form, list and search views, a window action, a menu, and inherited views
  with XPath.
- S4. Security (choice: "Seguridad: ACL, grupos, record rules"): in `odoo-security`,
  `ir.model.access.csv`, groups, record rules, multi-company rules.
- S5. Tests and frontend JS (choice: "Tests y frontend JS: TransactionCase, Owl, tour"): in
  `odoo-testing`, a `TransactionCase` model test and an `HttpCase` tour; in `odoo-views-frontend`, an
  Owl component or field widget registered in its registry.
- S6. Per-series files (choice: "Fusionar en las 4 skills de código, mantener en las 2 (Recomendado)"):
  the content of `references/15.0.md` and `references/19.0.md` of `odoo-backend`,
  `odoo-views-frontend`, `odoo-security` and `odoo-testing` moves into the recipes and those files are
  removed; `odoo-environment` and `odoo-module-lifecycle` keep theirs. The Gentle Shell prompt line
  "load the odoo-* skill (references/19.0.md) first." (`pi/lib/project.ts:196`,
  `pi/tests/project.test.ts:329`) names the recipes instead; README, CHANGELOG and docs that name the
  per-series files follow.
- S7. Verification (choice: "Test que parsea snippets + campo real (Recomendado)"): a unittest parses
  every fenced `xml`, `python` and `csv` block of every recipe (and fails on a broken link between
  skill files), and fails when `tools/odoo_versions.py` has a series a recipe's `Checked against:`
  line does not list; the release gate (docs/release-gate.md) adds a step where an agent builds a small
  module using only the recipes and installs and tests it on 15.0 and on 19.0 with `oasis
  test-module`, and the row records it.
- S8. More series (user: "que pasara cuando agregue mas versiones de odoo?"; choice: "Sí, así
  (Recomendado)"): the differences in a recipe are a table with one row per point that changed:
  the point, the series it changed in ("since"), the form before, and the source `path:line`. Only
  what was read in a local source goes in; while only 15.0 and 19.0 are checked, a "since" means
  "after 15.0, by 19.0 at the latest" and the recipe says so. Each recipe has a `Checked against:`
  line naming the series it was verified on. Adding a series confirms the existing rows, adds the
  points that series changed and extends `Checked against:`; `odoo-environment` and
  `odoo-module-lifecycle` get one more `references/<series>.md`.

## Not in this version

- Recipes for reports (QWeb PDF), wizards, mail/activity mixins, portal controllers, migrations.
