# v0.15.0 (plan): operate Odoo 15.0 next to 19.0

Approved by the user ("obvio", L4). One oasis-workspace.toml per
project with sections per series (decided in memory oasis/odoo15-support); a checkout works with
the series its modules declare.

## Specs

- S1. User (2026-11-25): "en mi repo de corpus cafe tengo ramas, entre ellas note que hay
  diferentes versiones para odoo 15 la herramienta podria resolver esto?"; "que pasaria con las
  bases, credenciales, entornos virtuales?"; "ahora si continuemos, checa lo relacionado a la
  investigacion para empezar a usar odoo15". oasis operates a 15.0 checkout (start, stop,
  restart, tests, update, databases, doctor, menu and panel) with its own source, environment,
  PostgreSQL, credentials, database prefixes, data and logs, fully separate from 19.0.
- S2. A 15.0 row in tools/odoo_versions.py, read from the local 15.0 source
  (/home/andres/Work/odoo/source/odoo-15/odoo): python 3.7-3.12 (odoo/__init__.py MIN/MAX),
  python_default 3.10, second_port_option --longpolling-port, demo off --without-demo and no
  --with-demo (demo is on by default in 15), --test-tags does not imply --stop-after-init, class
  filter yes, --dev features ipdb pdb pudb wdb qweb reload werkzeug xml, all = pdb reload qweb
  werkzeug xml, reload packages inotify/watchdog, postgres_default 14, postgres_min 12 (see L3).
  Every place that assumes 19 uses the table instead: the demo-on argument (tools/actions.py,
  tools/dev_users_runtime.py emit --with-demo), --stop-after-init for tests, the dev menu, and
  view-info knows `tree` (tools/xml_info.py TYPE_ORDER).
- S3. workspace_version 2: [tooling] holds the common keys and may use `{series}` in paths
  (config = "config/{series}", logs = "logs/{series}", data = "data/{series}");
  `[series."x.y"]` holds what differs (environment, compose, env file, odoo.conf, db port,
  compose project, dev_prefix/test_prefix). A checkout's series: oasis-checkout.toml
  `odoo_version`, else its manifests (the S11 reading of v0.14.0), else the workspace default.
  Precedence: checkout > workspace [series] > [tooling] > machine [series] > table defaults. A
  checkout whose series has no section is refused naming `oasis setup`. doctor fails when two
  series share db port, prefix or compose project. workspace_version 1 keeps working as one series.
- S4. Series exceptions (user chose "Excepción declarada"): a list of modules the series guard
  ignores, declared in the series section (e.g. `series_exceptions = ["report_xlsx"]` for
  corpus-cafe 15.0, whose report_xlsx declares 16.0.2.0.2); doctor shows each exception.
- S5. `oasis setup` in a checkout of a series the workspace lacks plans the
  `[series."x.y"]` section and the machine file entry, adopting existing files (e.g. corpus-cafe
  config/odoo-15/: compose with postgres:14-alpine on 5415, odoo.conf with dbfilter ^cc15_).
- S6. oasis-checkout.toml joins the settings-file ask tier (user: "Sí, que pida confirmación"):
  checkout_slug there moves the database namespace.
