# oasis v0.17.0: one name for every Odoo series, skills per series, CI

oasis stops carrying the `odoo19` name: one install directory, one command, skills per topic with a
reference per series; adopted environments are only reported; GitHub Actions runs the suites.

## Specs

- S1. Adopted environments (user: "esos problemas creo que no los debe gestionar la herramienta sino solo
  dar aviso pero sin que la herramienta se meta"; choice: "Solo avisa (WARN), nunca lo toca
  (recomendado)"): when the environment was adopted (`--environment`, not created by oasis) and does not
  match the locks, doctor and `doctor --environment` report it as WARN with the command that would sync
  it, never FAIL, and no command but an explicit `bootstrap --apply` changes it. The lock comparison
  normalizes distribution names on both sides (PEP 503: `zope.event` installed by pip is `zope-event` in
  the lock), so a package that is installed is never reported missing (field: `missing_package=zope-event==5.0`
  on billing-o15 while `zope.event-5.0.dist-info` is installed and imports).
- S2. Skills per series (user: "no habiamos quedado que se referenciara a las skills correspondientes en
  su respectivo .md?"; layout A decided earlier): one skill per topic named `odoo-<topic>` (backend,
  environment, module-lifecycle, security, testing, views-frontend), its SKILL.md common to every series
  and pointing to `references/15.0.md` and `references/19.0.md` for what differs, chosen by the checkout's
  series (`oasis doctor` series=). The `odoo19-*` skills are removed (choice: "Se borran (recomendado)").
- S3. No `odoo19` name (user: "quiero quitarme el odoo19 osea que solo es para esa version"; choice:
  "Todo en 0.17.0, sin transición"): install.sh installs into `~/.agents/skills/oasis` and removes
  `~/.agents/skills/odoo19`; the `odoo19` entry-point alias, the inactive `odoo19_*` tool aliases and
  `/odoo19` in Gentle Shell are removed; project wrapper templates and every doc, skill and message use
  `oasis` and the new directory. A contract change: AGENTS.md Compatibility, README and CHANGELOG say so,
  with what a user runs to update a project whose wrapper calls the old path.
- S4. CI (choice: "Tests en cada PR y en main (recomendado)"): GitHub Actions runs the Python suite and the
  node suite on every pull request and on pushes to main, with Python 3.12 for the tools and a short job
  with Python 3.8 and 3.9 for what runs inside Odoo 15 environments.
- S5. Release gate (AGENTS.md Releases step 0): the field run of docs/release-gate.md with the new names;
  the release is blocked if handoffs grow over 0.16.0 (1, genuine).
