# oasis v0.21.0: remove what is no longer used

Audit of the repository (four read-only explorers, 2026-11-28) and removal of dead code, duplicated tests,
stale docs and the old transitions. The per-series workspace layout planned as v0.21.0 moves to v0.22.0.

## Specs

- S1. The install ships only what agents use (user: "Sí, todo el grupo 1 (Recomendado)"): `install.sh`
  no longer installs `odd/` nor `tests/`; `docs/install.md` and the install/bundle tests agree.
- S2. Tests that repeat rules already pinned elsewhere, or only compare wording of the README or the CI
  YAML, are removed (audit: `tests/test_check_environment.py` DependencyLockTests duplicate
  `tests/test_locks.py`; `tests/test_doctor_environment.py:146-154`; `tests/test_ci_workflow.py:36-42`).
- S3. `pi/` keeps no test-only code nor dead fallbacks: `blockedProgram`, `isRunLog`, `HARNESS`,
  `POLICY_VERSION` and the `ODOO19_PROJECT_ROOT` root fallback go; the tests use the public functions.
- S4. `tools/` keeps one copy of each helper (`sibling()` in 7 files, `git_env` in 2), no stale history
  comments, no branches that only differ by a message suffix.
- S5. Docs nothing needs go: the 19.0 Chromium socket incident note (its cause moves to
  `docs/troubleshooting.md`) and `docs/verification.md` (its index rows too).
- S6. The odoo19 transition and pre-0.17.0 leftovers go, with a contract note (user: "Sacarlos todos con
  nota de contrato"): the `install.sh` block that removes `~/.agents/skills/odoo19`, doctor's
  `project_wrappers` check, reading the `.odoo19-agent.toml` profile (migrate, config, gc, doctor, the
  entry point's legacy gate), the guard's `odoo19` entry point and `skills/odoo19/tools`, the old lock
  format, the pre-0.8.0 run logs, and the `.logins` WARN. A command left with nothing to do is removed too.
  README and CHANGELOG say what a user with an older project does.
- S7. The deprecated aliases go now (user: "Sacar los tres ahora"): `start-database`,
  `recreate-database-volume` and `check-environment` (tool scripts, project wrapper, the entry point,
  `oasis policy`, the guard's generated policy, docs, tests); calling one behaves like any unknown
  command; README and CHANGELOG say which name to call.
- S8. The plans of released versions stay in the repository, not installed (user: "Dejarlos en el repo,
  no instalarlos (Recomendado)").
- S10. `docs/architecture.md` explains how oasis is built (user: "quiero arquitectura de oasis porque ya me
  perdi que hace cada cosa y como esta conectado, es mas si algo tiene coneccion ajajaj, las tools no se en
  que modo crecieron"; choice: "Agregar docs/architecture.md en esta limpieza (Recomendado)"): the layers and
  who calls whom, the commands by job with their files, the shared modules, where the policy lives and how
  the guard and the scripts enforce it, and the growth problems as follow-ups; written after T1-T4 so it
  describes the cleaned code; indexed in docs/README.md.
- S11. One door (L7, user: "Borrar las plantillas en v0.21.0 (Recomendado)"): the `project-wrappers/`
  templates go; a project's existing copies keep working while the tool names exist; README and CHANGELOG
  say to call `oasis <command>` instead; docs that tell to copy them are updated.
- S9. Release v0.21.0 with the release gate's field run.
