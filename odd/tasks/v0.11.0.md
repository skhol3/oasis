# v0.11.0 — safer destructive operations, server control, fixes

## Specs

- S1. User (2026-11-24): "luego de la documentacion hacemos auditoria para ver que falta respecto a
  comandos para levantar, actualizar, elegir puerto, levantar con test y demas. En si como
  mejorarias esta parte para el harnes". Audit: memory oasis/operations-audit. On the destructive
  commands, after comparing Odoo tools (odoo-activity, odoo-dev-panel, odoo-cli): "si creo que
  ahora tenemos algo mas solido". Accepted proposal: soft delete and a plan in the command for
  everyone; an ask tier in the Gentle Shell layer; agent permission set by the user in the
  configuration, never by the agent. Plus "Seguridad y arreglos" and "Servidor". Gentle Shell is
  not modified.
- S2. Trash instead of drop: `drop-database <name>` renames the managed database (and its
  filestore under the data dir) to a trash name that keeps the namespace prefix and carries the
  drop time (shortened with a hash to fit 63 bytes), and prints the plan first (database, size,
  open sessions, filestore path, trash name). `--terminate` keeps its meaning. `oasis trash`
  lists trashed databases of the checkout with their age and size; `oasis trash restore <trash
  name>` renames back (refused when the original name exists); `oasis gc --apply --trash
  [--older-than <days>]` drops trashed databases and their filestores (default 7 days). Plain
  `gc --apply` keeps dropping only orphaned disposable test databases.
- S3. Agent tiers in the Gentle Shell layer (pi/extensions, pi/lib): allow (tests, verify, gc,
  gc --apply, stop of the checkout's server, install, update, create, trash list/restore),
  ask (drop-database, stop --database, gc --apply --trash), deny (as today: migrate,
  worktree-init, menu, direct odoo-bin/psql/dropdb). Ask shows a dialog with the exact command
  and asks to type the database name (or `yes` for stop --database and gc --trash); no answer,
  a wrong answer or no UI (subagent, headless) blocks with a clear reason. Each ask decision is
  recorded as a session entry that is not sent to the model.
- S4. Configuration owned by the user: workspace/profile key `[tooling].agent_destructive` with
  `ask` (default), `deny` or `allow`; read by the layer from tools/config.py; no tool argument
  can change it. doctor shows its value.
- S5. Fixes: `start --detach` probes the configured http interface (not only 127.0.0.1) and fails
  when the server does not listen; messages name the remedy ("already running: run oasis stop",
  "port <p> in use by checkout <slug>"); `odoo-shell` refuses extra arguments.
- S6. Server: `oasis restart [odoo options]` (stop then start detached, same record and port);
  `stop --force` (SIGKILL after the graceful timeout); `status` lists the servers of every
  checkout of the repository with port, pid and database; the menu/panel gain restart and a
  live log view (follow) and show the server state.
