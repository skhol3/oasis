# v0.12.0: the menu acts per checkout, and environments for any series

The action menu (terminal and Gentle Shell panel) acts on the current checkout, shows what will
run, and starts or restarts with a chosen database, dev mode and port. bootstrap and
check-environment follow the workspace's declared environment instead of a fixed Python 3.12.

## Specs

- S1. User: "si corrige los bugs que encontro la guia del workspace, por se supone que sera a
  futuro para cualquier odoo". bootstrap works in a workspace checkout (no dev/runtime
  assumption) and creates the environment with the Python the workspace declares for the selected
  environment; check-environment checks that declared Python (within the series' supported range
  from tools/odoo_versions.py), not a fixed 3.12.
- S2. User: "como estamos trabajando por worktree, el menu debe hacer las acciones respecto a
  este." list-databases and the menu's managed database list show only the current checkout's
  databases (its prefixes and slug); a worktree no longer lists main's or other worktrees'.
- S3. User: "como elegimos base, test, demo, start, restart, port,...". Start without a
  database warns that Odoo will use odoo.conf's db_name, and the menu asks before going on. One
  "Start / restart" action asks, in order: database (default: the last recorded for this
  checkout, else the checkout's development database), dev mode, port (the one it will use,
  editable), then shows the exact command and confirms.
- S4. User: "checa que valores usa odoo 19 para dev, recuerda que luego daremos soporte para
  otras versiones de odoo". Dev features are declared per series in tools/odoo_versions.py; the
  selector is closed (no free text) and built from that table. Odoo 19.0 (source
  odoo/tools/config.py:428-437, ALL_DEV_MODE at :29): access, qweb, reload, replica, xml; "all" =
  access,qweb,reload,xml. reload needs the inotify or watchdog package (odoo/service/server.py
  1663-1675), else Odoo logs a warning and disables it.
- S5. User: "ademas de la linea con el checkout estaria bien mostrar el comando que se
  ejecutara, analiza el mejor lugar para ponerlo". The menu header shows the checkout (main or
  the worktree slug), the server state and the default database; the command that will run is
  shown where it is best read (decided from the menu map, see the Log).
- S6. "Repeat last action" is the first entry once an action ran in this checkout; it repeats the
  same action with the same answers, after the same confirmation.
- S7. Catalog changes are additive: an installed panel of an older version keeps working.
  Agents never use the menu.
