## Specs

- S1. User picked the scope proposed from the pending list ("si dale"): "Los puntos 7, 8 y 10, más
  el 20 y el 22 como limpieza". 7: "Correr un solo test o una clase, para iterar sobre un fallo sin

  tuyo." 20: "`ssh`, `su`, `source` y `eval` cuentan como lectores de un heredoc solo en posición
  de comando." 22: "Test del aviso de progreso que depende del reloj."
- S2. `test-module [--compact] [--only <Class[.method]>] <module> [test_database]`: `--only` runs
  the tests of one class, or one method of it, with `--test-tags /<module>:<Class>[.<method>]`.
  Anything else as its value exits 2 before any effect. Without `--only` the command line is
  unchanged. `oasis_test_module` takes `only`.
- S3. `update-module [--compact] <module> <database>`: `--compact` keeps stdout/stderr in the run
  log directory and prints `phase=update database=<db> exit=<n>`, `stdout_log=` and `stderr_log=`.
  Without `--compact` nothing changes. New agent tool `oasis_update_module` (module, database):
  errors, grouped warnings, the control line and the log paths; no test result line. The overlay
  gives it to the worker only (verify stays read-only).
- S4. `migrate --plan [--workspace <dir>]` prints the plan and never applies: `--plan` with
  `--apply` is a usage error (exit 2). The bash guard lets the agent run exactly that form
  (`--plan`, optionally `--workspace` with a literal absolute path); every other migrate form stays
  user-run, the plain dry run included.
- S5. Guard: `setsid`, `stdbuf`, `ionice` and `doas` are wrappers (a blocked program behind them is
  blocked; a heredoc reader behind them is detected); tests pin ssh, su, source and eval as readers
  behind wrappers and in brace groups.
- S6. The heartbeat test does not assert wall-clock values.
