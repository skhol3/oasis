# v0.12.1: panel list scrolling and filter, /oa completions, the native Odoo command

First live use of the Gentle Shell panel (corpus-cafe main checkout, ~30 databases) found that the
start/restart form cannot scroll its list; the user also wants subcommand suggestions while typing
the command name and the native odoo-bin command in the panel.

## Specs

- S1. User: "en el menu pasa lo siguiente, como hay muchas bases no puedo deslizarme cuando lista
  las bases, solo me deja ver esas que ves en la foto, como tal no veo el selector hasta estar en
  las ultimas bases". The panel's start/restart form shows a window of its choice list that
  always contains the selected row, with `↑ n more` / `↓ n more` markers; the header and the
  command lines stay visible. Cause: pi/ui/menu-panel.ts:203-204 keeps the tail of the form.
- S2. Filter (user chose "Sí" to "¿Agregamos filtrar la lista escribiendo parte del nombre?"):
  typing in a list narrows it to the options containing the typed text (case-insensitive);
  backspace edits the filter; the filter is shown; `(type a name)` and `(none)` stay available.
- S3. User: "al poner /oasis ya me gustaria tener la sugerencia de lo demas, actualmente debo poner
  completo /oasis de alli me salen las alternativas". Typing `/oa` (or `/odoo`) without a space
  suggests `/oasis <subcommand>` entries (and `/odoo19 <subcommand>`), through the public
  `ctx.ui.addAutocompleteProvider`, delegating everything else to the existing provider. No new
  command names.
- S4. User: "En el panel por otro lado, me gustaria ver el comando nativo, no lo que hacemos
  nosotros, es posible?"; chose "Solo el de Odoo" and "Abreviado (~ y …)". `start --print-command
  [options]` and `restart --print-command [options]` print the odoo-bin command line start would
  exec (python, odoo-bin, -c conf, addons path, data dir, ports, the passed options), one
  shell-quoted line, exit 0, with no side effects (no compose, no record, no Odoo run; a port probe
  only as start already does to choose a port). It never prints the conf contents or a password.
  The panel shows this native line instead of the oasis line in the start/restart form, with the
  home directory as `~` and long values (addons path) shortened with `…`; the full line goes to
  the action's result entry.
- S5. Compatibility: additive only (a new option, no changed output of existing commands);
  agents may run `--print-command` (read-only).

- S6. README and docs/install.md say plainly which install does what: `install.sh` installs the
  skills and the `oasis` CLI (wrapper) into `~/.agents/skills/odoo19` for any agent and the
  terminal; the Gentle Shell (Pi) package adds the oasis tools, `/oasis` and the panel to Gentle
  Shell or Pi. The README speaks of Odoo in general with 19.0 as the supported series today;
  the odoo19 names stay (contract) until a second series.
- S7. Vanilla Pi: the package works there (L5); docs do not mention vanilla Pi (user: "lo de pi no
  lo menciones en la docuemntacion"). `/oasis setup` on a host without
  Gentle Shell says the subagent overlay applies only to Gentle Shell and writes nothing.
