# v0.6.0 — faster test iteration and a version-neutral harness

Odoo 19 stays the only supported series; what the harness says and does about the series comes
from `odoo_version` and the capability table, so another series is a table row away.

## Specs

- S1. User: "por le momento seguimos enfocados en odoo19 pero orientado a odoo en general"; to the
  proposed scope ("Reutilizar la base entre corridas de test", "Herramientas de consulta",
  "Textos según `odoo_version`", "Tabla de capacidades completa, con el test que la protege"):
  "si". Split owned: 0.6.0 holds the first, third and fourth; the query tools go to 0.7.0.
- S2. `test-module --reuse`: keeps a working test database between runs. Its name is the explicit
  argument, else `tooling.test_database`, else `<test_prefix>[<slug>_]<module>`. When the database
  exists and the module is installed in it, the run updates the module (`-u <module>`) and runs the
  tests; otherwise the database is reset and the module installed, as without `--reuse`. Nothing
  is dropped at the end. `--compact` adds `database_lifecycle=reused mode=<install|update>`.
  Without `--reuse` every command line and output is unchanged. `oasis_test_module` takes `reuse`.
- S3. The Gentle Shell layer names the project's Odoo series from its configuration instead of a
  fixed "Odoo 19" (prompt section, status, tool labels and descriptions, messages).
- S4. What is still tied to 19.0 in the tools goes through the capability table: the class filter
  of `--only`, and the remaining series-specific options or checks; a test fails when a tool
  writes a series-specific Odoo option outside the table.
