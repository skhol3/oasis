# Location independence (v0.4.0)

One workspace file at the project root replaces per-checkout profiles, so checkouts and worktrees
work at any depth, nothing location-dependent is written into files, and the environment
contract is checked up front. Existing `.odoo19-agent.toml` profiles keep working.

## Specs

- S2. Accepted principle 1 (one anchor): "Un ancla, y todo relativo a ella ... que oasis lo encuentre subiendo directorios, igual que git encuentra `.git` ... Las rutas se escriben relativas al archivo que las declara, no al checkout. Un checkout puede estar a cualquier profundidad. Los worktrees no necesitan copia del perfil."

- L12. T2 design (owned):
  - `tools/odoo_versions.py`: one table `CAPABILITIES = {"19.0": {...}}` (only 19.0 now; 12.0/15.0 values from L6 stay in this log, not in code, until verified). Keys: `python` (min, max as "3.10", "3.14"), `postgres_min` (13), `second_port_option` ("--gevent-port"), `demo_off_args` ([] for 19, since 19 loads no demo by default; the adapter renders it instead of a bare `--without-demo`), `test_tags_implies_stop` (True). The selected environment's `python` must lie within the capability range; the legacy `python_version = '3.12'` requirement is kept for profiles. Unknown name -> clear error listing the declared names.
  - Every Odoo invocation uses the emitted values: `start` passes `$ODOO_SECOND_PORT_OPTION=<port>` instead of a literal `--gevent-port`; `test-module`/`verify-module` render `$ODOO_DEMO_OFF_ARGS` instead of a literal `--without-demo`; no other literal version-specific Odoo flag remains in tools/ (grep proves it).
