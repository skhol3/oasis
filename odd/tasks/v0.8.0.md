# v0.8.0 — oasis names inside the harness

The harness stops naming Odoo 19 in what it sets and writes: environment variables, the log
directory layout, CLI texts and the Gentle Shell extension. Everything existing keeps working.

## Specs

- S1. User (2026-11-23): "continua con pendientes de oasis  1, 2, 3, 4" (1: cleanup of `odoo19`
  names; 2: the flaky test; 3: action panel; 4: `module-info`). This document covers 1 and 2.
- S2. Environment variables. User chose: "`OASIS_*` nuevas, `ODOO19_*` siguen valiendo
  (recomendado)". Every `ODOO19_<NAME>` a user, wrapper or test may set (`PROJECT_ROOT`,
  `ENTRYPOINT`, `TOOLS_DIR`, `COMPOSE_LOCK_TIMEOUT`) is read as `OASIS_<NAME>` first and as
  `ODOO19_<NAME>` when that is unset. The entry point exports both names with the same value.
  Variables that only pass between a tool and the child it starts itself (`RUN_RESULT`,
  `REUSE_RESULT`) are renamed to `OASIS_*` without a fallback. Error messages name `OASIS_*`.
- S3. Log directory. User: "y si solo dentro de logs estan las carpetas de main y los demas
  worktrees?". With `[tooling].logs` set, compact runs go to `<logs>/<slug or main>/run-<id>/`
  (no `odoo19/` level). Without it the legacy default `dev/logs/odoo19/` is unchanged. Existing
  directories are never moved or deleted. `oasis_test_summary` accepts run logs of both layouts.
  The same containment checks apply (a run directory may not escape the logs directory).
- S4. CLI texts: no message, help or usage says "Odoo 19"; help that tells the user to run a
  command names the invoked entry point (`oasis gc`, or `odoo19 gc` through the alias) instead of a
  fixed `odoo19`.
- S5. Gentle Shell extension: `pi/extensions/oasis.ts` (package.json points to it); the prompt
  section key and tag are `oasis`, the status message type `oasis-status`.
- S6. Unchanged, on purpose: the install directory `~/.agents/skills/odoo19` and the skill names
  `odoo19-*` (decision pending with the user), the entry point alias `odoo19`, the tool aliases
  `odoo19_*`, `/odoo19`, the legacy profile name `.odoo19-agent.toml`, and every command's
  options, exit codes and output other than the texts of S4.
- S7. The test `test_shared_conf.SharedConfTests.
  test_linked_worktree_gets_the_rewritten_addons_path_everywhere` failed once in a full run on
  main and passed alone and in the next full run. Find the cause with evidence and make the test
  deterministic; if the cause is in the tool, fix the tool and pin it with a test.
