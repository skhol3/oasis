# v0.10.0 — module-info

A one-screen map of one Odoo module from source, next to model-info, view-info and xmlid-info,
so the agent (and the user) see a module's architecture without reading its files.

## Specs

- S1. User (2026-11-21), after trying the query tools on corpus-cafe `oa_payment_planner`: "haber
  probalo vos, con esto ya podria obtener la arquitectura de cada modulo?"; the answer showed the
  per-model tools work but the overview needed the manifest and a grep of `_name`/`_inherit` by
  hand; user: "anota otra tarea para despues". Scheduled by the user (2026-11-23): "continua con
  pendientes de oasis 1, 2, 3, 4" (4 = module-info).
- S2. `module-info <module>`: from the module's source only (same roots as model-info, the first
  module with the name wins; ast for Python, expat for XML, csv for CSV; nothing imported or
  executed; no environment, service or database):
  - header: technical name, version, summary or name, `depends`, and the root it was found in;
  - models defined (`_name`, with `_description` when set, and whether it is transient) and models
    extended (`_inherit` without `_name`), each with the number of fields it adds or overrides and
    the file:line;
  - views: base views per model and type, and extensions per inherited view (counts, with the
    XML ids);
  - menus as a tree (name and XML id), and actions (window actions with res_model, server actions,
    reports);
  - security: access rules (ir.model.access.csv lines per model with the groups and the CRUD
    flags) and record rules (ir.rule with model and groups);
  - data: the manifest `data` and `demo` files in order, crons (ir.cron with interval and model),
    and files present on disk but not listed in the manifest;
  - tests: the test modules and test classes.
  Each section is capped with the count of the rest; output stays compact (about one screen for
  a module like oa_payment_planner).
- S3. `--section <name>` prints only one section, uncapped (models, views, menus, actions,
  security, data, tests). Unknown module: exit 1 `module not found: <name>`; usage errors exit 2.
- S4. Agent tool `oasis_module_info` (module, optional section), active in Odoo projects and in
  the overlay of both subagents (read-only); prompt section line kept within the existing budget.
- S5. Nothing existing changes; `module-info` is a new command (README note).
